01 / GET STARTED

Install and open

  1. Open Blender 4.5 or Blender 5.x and go to Edit → Preferences → Add-ons.
  2. Open the menu in the top-right corner and choose Install from Disk.
  3. Select stage_tools-1.0.0.zip. Install the ZIP directly.
  4. Enable StageTools if it is not already enabled.
  5. In the 3D Viewport, press N and open the StageTools tab. The panel title is StageTools Engine.

Disable the three older utilities if they are installed, so the consolidated panel is the one you use.

Before changing production assets

Save your scene. The operators support Blender Undo. Normalization changes mesh geometry, and material pruning intentionally merges materials by name.

02 / ASSET VECTOR NORMALIZER

Prepare static meshes

Select one or more mesh objects in Object Mode. Each selected asset is processed independently. The tool measures the world-space vertex bounds, finds the bottom center, bakes the chosen correction into a separate mesh datablock, and resets rotation, scale, and delta transforms.

ButtonResult
Normalize for UE5Bakes a −90° rotation around Z. This maps an assumed Blender +Y forward direction to +X.
Normalize for MayaBakes a +90° rotation around X. This maps an assumed +Y forward direction to +Z.
Freeze Blender MatrixBakes the existing world rotation and scale without an additional axis correction.

The final mesh has its bottom at local Z = 0 and is centered around local X = 0 and Y = 0. The object origin is placed at the original world-space bottom-center position. After an axis correction, the geometry is re-centered above that origin.

Transform behavior

Object translation is retained at the computed pivot; the final matrix is a translation matrix. Blender has no general transform-history stack to erase. These buttons bake transforms, and do not configure exporter axis settings, engine units, or FBX options. Applying an axis-correction button again rotates the mesh again.

Supported inputs

  • Editable static meshes containing vertices, with nonzero scale.
  • Meshes shared by several objects are copied before modification, protecting the other users.
  • Shape-key coordinates are transformed with the mesh.
  • Editable child objects retain their world placement.

Parented, animated, constrained, modified, and rigid-body mesh objects are rejected. Prepare a separate static export copy for these assets. Non-editable linked meshes must be made local before normalization.

03 / MATERIAL NETWORK PRUNER

Consolidate material variants

Click Purge Duplicate Materials in Object Mode. No selection is required: the tool scans mesh material slots across the Blender file.

Example

If Steel and Steel.001 exist, mesh slots using Steel.001 are assigned to Steel. Repeated numeric suffixes are stripped when looking for the master.

  • A matching unsuffixed local master must already exist.
  • Protected linked data and unsupported assignments are skipped and reported.
  • Unused local material datablocks with zero users are removed, including unrelated zero-user materials.
  • Fake-user materials and materials still referenced elsewhere remain.
Name-based merging

The tool does not compare shader nodes, textures, or material values. A numerically suffixed material may contain intentional differences. Review material names before purging.

The completion report lists remapped slots, removed materials, and skipped operations. Other orphan datablock types are not purged.

04 / CAMERA FRUSTUM ISOLATOR

Focus the viewport

  1. Choose a camera in the panel’s Camera picker. Leave the field empty to use the scene’s active camera.
  2. Use a perspective or orthographic camera in the active view layer.
  3. Click Isolate Frustum View.
  4. Click Clear View Isolation to show objects again.

The tool evaluates mesh bounding boxes through the dependency graph, transforms instance bounds into camera space, and tests them against the camera’s side planes and near/far clipping distances. Objects are hidden only when their bounds are completely outside a frustum plane.

Linked assets and instances

Linked collection instances are evaluated at their instance transforms. Visibility is controlled on the local instancer rather than by editing the linked source mesh. Library overrides use editable visibility properties where available; protected objects use view-layer hiding when Blender permits it.

Generated instances share their owning object’s visibility. If any evaluated mesh instance for an owner intersects the camera frustum, the owner stays visible. Source meshes needed by an in-frame instance are also retained.

Scope and limits

Isolation is a manual snapshot. Run it again after moving the camera, changing geometry, or changing frames. It is a conservative bounding-box test, so some objects that do not actually intersect the frame may remain visible. It does not test occlusion.

  • Isolation first clears object hiding on candidate meshes and instancers in the active view layer so previously hidden candidates can be evaluated.
  • Editable objects use hide_viewport, which can affect their visibility in other scenes and view layers sharing those objects.
  • Clear View Isolation attempts to clear hide_viewport for every object datablock and local hiding in the active view layer. It does not restore a previous visibility snapshot.
  • Hidden or excluded collections are not made visible. Objects absent from the evaluated dependency graph cannot be reliably classified.
  • Render visibility is unchanged. Panoramic cameras are unsupported.
05 / DAILY USE

A practical sequence

  1. Save a working copy of your scene.
  2. Prepare static export meshes and choose the required normalization button once.
  3. Inspect pivots and orientation, then configure the exporter for the destination pipeline.
  4. Review suffix-named materials and purge only when they should share their master.
  5. Choose the layout camera and isolate its frustum.
  6. Clear isolation before reviewing the full scene, or rerun isolation after scene changes.

07 / RELEASE DETAILS

One suite, three sources

StageTools consolidates the supplied Asset Vector Normalizer, Dirty Material Pruner, and Camera Frustum Isolator add-ons into one extension with a single panel and shared registration.

The installable ZIP contains __init__.py, blender_manifest.toml, and the GPL LICENSE. This offline guide.html is distributed separately and is excluded from the ZIP. The original add-on directories are preserved separately in the workspace.

Minimum declared version: Blender 4.5.0, with no upper version limit. The implementation uses APIs shared by Blender 4.5 and Blender 5.x. Automated integration checks ran in Blender 5.1.2 for normalization, shared mesh protection, material remapping, perspective and orthographic isolation, local collection instances, linked library collection instances, clear isolation, and registration cleanup. The extension ZIP passed Blender’s manifest validator. Blender 4.5 is not installed in the verification environment, so 4.5 runtime compatibility and every library-override configuration remain unverified.

Manifest field names and tags follow Blender’s extension schema. The manifest declares SPDX:GPL-3.0-or-later and requests no permissions.
